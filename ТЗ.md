# 📄 Техническое Задание: Telegram RAG-бот по документам

## 1. Цель проекта
Разработать Telegram-бота с архитектурой RAG (Retrieval-Augmented Generation) для ответов на вопросы по загруженным PDF-документам. Проект должен продемонстрировать навыки работы с LLM, векторными базами данных, Docker и написания чистого кода на Python без использования тяжелых фреймворков (LangChain/LlamaIndex).

## 2. Технологический стек
*   **Язык:** Python 3.10+
*   **Telegram Bot:** `aiogram 3.x` (асинхронность, поддержка стриминга).
*   **Векторная БД:** Qdrant (запуск через Docker).
*   **Реляционная БД:** PostgreSQL (для метаданных пользователей, истории и статусов файлов). Миграции: `alembic`.
*   **Обработка PDF:** `PyMuPDF` (fitz) — для парсинга текста, извлечения картинок и рендера страниц в PNG.
*   **LLM & Embeddings:** API OpenAI (`gpt-4o-mini` / `text-embedding-3-small`) или локальные модели через Ollama.
*   **Инфраструктура:** `Docker`, `Docker Compose`.
*   **Управление зависимостями:** `pyproject.toml` (Poetry или uv).

## 3. Функциональные требования (MVP)
Бот должен работать в парадигме «Один пользователь — одна изолированная коллекция».

### 3.1. Работа с документами (Ingestion)
*   **`/start`**: Приветствие, краткая инструкция.
*   **`/upload`**: Прием PDF-файлов от пользователя (лимит размера, например, до 20 МБ).
*   **Пайплайн обработки**:
    1. Извлечение текста (с учетом разбивки на страницы).
    2. Чанкинг (разбивка на куски с перекрытием, например, 500 токенов, overlap 50).
    3. Векторизация (получение эмбеддингов).
    4. Сохранение в Qdrant с метаданными (`user_id`, `file_name`, `page_number`).

### 3.2. Взаимодействие (Retrieval & QA)
*   **Текстовый запрос**: Пользователь пишет вопрос. Бот ищет релевантные чанки в коллекции именно этого пользователя.
*   **Генерация ответа**: Строгий системный промпт (anti-hallucination: «Отвечай ТОЛЬКО на основе предоставленного контекста. Если ответа нет, так и скажи»).
*   **Стриминг**: Ответ должен появляться в чате постепенно (использование `edit_message_text` в aiogram).
*   **Citations (Источники)**: В конце ответа бот должен указывать: `Источник: документ.pdf, стр. 12`.
*   **`/reset`**: Очистка контекста текущего диалога.

## 4. «Вау»-фичи (Для портфолио)
*Реализовать минимум 2 пункта:*
1.  **Highlight источника (Визуальный вау-эффект):** Бот возвращает не просто текст, а рендерит страницу PDF в картинку (`PyMuPDF`), накладывает полупрозрачный желтый прямоугольник на найденный абзац и отправляет фото в чат.
2.  **Eval-скрипт (Оценка качества):** В папке `eval/` лежит `questions.jsonl` (10-15 пар вопрос-ответ). Скрипт `run_eval.py` прогоняет их через систему и считает Accuracy. В README пишем: *"Accuracy: 87% на тестовом датасете"*.
3.  **Мультидокументность:** Возможность загрузить несколько файлов и указывать в вопросе: «Сравни условия в договоре_1.pdf и договоре_2.pdf».
